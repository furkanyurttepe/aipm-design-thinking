# Design Thinking Workflow

Apply this method to whatever challenge the group supplies. Do not assume a
product answer; this Skill contains the method, not a solution.

## Evidence rules

- Use only evidence the group supplied (interview notes, observations, desk
  research). Never invent quotes, numbers, or participants.
- Label every important claim as one of: **Evidence** (with source ID),
  **Interpretation**, **Assumption**, or **Open question**.
- Treat AI-generated personas, reactions, or simulated participants as
  **SIMULATED**. Keep them separate from real observations.
- When evidence is missing, write an open question instead of a guess.
- Do not turn a single reaction into a universal requirement; note sample size
  and confidence.
- Before citing an evidence ID, re-read it and check that it actually supports
  the claim; drop citations that only relate to the topic.
- Observation tables record only what happened. Words such as "because",
  "so", "seems" or "probably" belong in an Interpretation section.

## Workflow and approval gates

1. **Frame** — Ask questions, propose a bounded scope (one person, one journey).
   ⛔ Wait for approval before creating files.
2. **Empathise** — Set up an evidence log. The group enters raw evidence. Keep
   raw evidence separate from interpretation.
3. **Define** — Cluster evidence, then draft persona, journey map (actor,
   scenario, goal, phases, actions/thoughts/feelings, pain points,
   opportunities), POV ("[User] needs [need] because [insight]") and HMW
   ("How might we help [user] [progress] when [context]?"). The HMW must not
   contain a solution. ⛔ Wait for approval of the problem frame.
4. **Ideate** — Generate several *materially different* directions. Keep
   generation separate from evaluation. Then propose criteria: user value,
   learning value, feasibility, risk. ⛔ The group selects the direction.
5. **Prototype** — State one learning question. Recommend the lowest fidelity
   that can answer it. Show files, flow, and test task before editing.
   ⛔ Wait for approval.
6. **Test** — Draft a neutral task ("Show me how you would…", "What would you do
   next?"). Do not explain the solution. The group records observations first;
   only then interpret.
7. **Iterate** — Propose a small set of changes, each linked to an observation.
   ⛔ Implement only approved changes.

## Collaboration log

After each delegated task, add a row to `ai-collaboration-log.md`: request,
what was accepted, edited, rejected, and the evidence or reason.

## Expected artifacts

`discovery.md`, `decision-log.md`, a prototype, `test-notes.md`,
